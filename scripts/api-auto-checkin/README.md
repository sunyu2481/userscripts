# 公益站自动签到助手 · 油猴版

在签到页上找到签到按钮并点击它。不预置站点类型，不拼接口地址，不主动发签到请求。

## 装

1. 安装 Tampermonkey
2. 打开 `https://raw.githubusercontent.com/sunyu2481/userscripts/main/dist/api-auto-checkin.user.js`，Tampermonkey 会弹出安装页面
3. 确认安装

> 也可以直接下载 `dist/api-auto-checkin.user.js` 拖进浏览器窗口。

## 自动更新

脚本头部带了 `@updateURL` 和 `@downloadURL`，都指向本仓库 `main` 分支的 `dist/` 产物。Tampermonkey 会定期检查，**当你发布新版本时，会自动提示更新**。

前提是发布时版本号要递增——油猴只认 `@version` 变大才更新。

### 发布新版

日常发布由仓库根目录的 `.github/workflows/ci.yml` 自动完成。修改源码或测试后，直接提交并推到 `main`：

```bash
git add -A
git commit -m "fix: 修复 xxx"
git push origin main
```

推上去后，CI 会自动递增所有脚本的 patch 版本号、构建脚本、运行测试，并把生成的脚本和 `dist/` 提交回 `main`。测试失败时不会提交发布产物，需要修复后重新推送。

发布前不需要本地运行 `node build.js --bump` 或根目录的 `node build.js`。如果要在本地预览或检查构建产物，仍可在本目录运行 `node build.js`（不递增版本号）。CI 提交完成后，Tampermonkey 下一次检查（默认几小时一次，或手动点「检查更新」）就会拉到新版本。

## 用

任意网页的 Tampermonkey 菜单 → 「打开签到面板」。

添加站点时填**签到页的完整地址**，也就是你平时手动点签到按钮的那个页面：

```
https://example.com/console/personal
https://example.com/check-in
https://example.com/#/checkin      ← hash 路由的也支持
```

填对页面比填对域名重要 —— 脚本要在这个页面上找按钮。

脚本元数据只匹配 HTTPS 页面，因此新增或导入的站点地址必须使用 `https://`。

地址会原样打开，不追加任何参数。hash 路由（`/#/checkin`）如果被前端在初始化时冲掉（落到首页），脚本会纠正回目标路由再找按钮。

点站点行的 `✎` 可以改**名称、地址、按钮和结果文案、仅访问模式**，都在同一个对话框里。添加时也能直接填名称和勾选仅访问。

同一个编辑框还可以为站点填写**签到按钮文案**和**成功结果文案**（逗号分隔）。填写按钮文案后，脚本只会精确匹配这些按钮，不会再从页面上的其它「每日签到」等入口中猜一个；留空则继续使用通用识别。结果文案只在站点提示语不在通用词表时填写。

「仅访问」适合每天打开一次页面就行、不需要点按钮的站点。勾上之后脚本打开页面就算完成，不去找签到按钮。这类站点在列表里带一个「仅访问」标记。注意它仍会检查登录态——如果打开后落在登录页，会报「需要先登录」而不是假装成功。

名称留空时脚本会尝试从页面 `og:site_name`、`application-name` 或标题里取。这个自动取名会过滤掉「签到」「打卡」「控制台」「Dashboard」这类功能词——很多站点标题是「签到 - XXX」，直接取第一段会得到"签到"。**一旦你手动改过名称，自动获取就不再覆盖它**；把名称清空则重新交给自动获取。

点「开始签到」后，脚本依次在后台标签页打开各站点的签到页，等按钮出现、点它、读结果。

**标签页默认留着不关**，方便你自己翻一遍核对结果。全部跑完后面板上会出现「关闭 N 个标签页」，点一下全部关掉（Tampermonkey 菜单里也有同样的命令）。想让它签完就自动关，在设置里勾「签完自动关闭标签页」——需要你处理的标签页仍然会保留。

一键关闭依赖 `GM_openInTab` 返回的句柄，这东西是活对象、存不进 `GM_setValue`，只能留在发起签到那个页面的内存里。所以刷新或关掉发起签到的页面后就没法一键关了，只能手动关标签页。

## 它怎么判断

**找按钮**：未配置站点文案时，收集页面上的可点击元素，按文案匹配（`立即签到`、`每日签到`、`签到领取`、`领取奖励`、`Check in` 等），文案越精确优先级越高。配置站点文案后只做精确匹配。文案挂在 `span` 上、点击挂在祖先按钮时也能找到。排除设置项、说明文字、禁用元素、隐藏元素。

转盘/抽奖式签到也支持：`开始转动`、`开始抽奖`、`点击抽奖`、`试试运气`、`Spin`、`Lucky Draw` 这些在表里。转盘结果通常在弹窗里，脚本只采信弹窗或响应里的明确结果，不会把转动期间或结束后的按钮置灰单独当成成功，也不会把这种结果弹窗当公告关掉。

**判已签**：未配置站点按钮文案时，页面上明确出现「今日已签到」这类状态。配置了站点按钮文案后，不会把页面其它区域的签到记录、说明文字当成已签；点击后新出现的明确「已签到」状态仍会采信。按钮被禁用可能只是页面仍在初始化，所以会继续等待，超时后标为「待确认」，不会单独判成已签。

**判人机验证**：只在可见的验证控件、验证弹窗，或内容很短且明确要求「请完成人机验证」的专门验证页上停下。安全设置里的「身份验证」、帮助文案里的「验证码」以及常驻的 reCAPTCHA/Turnstile 被动徽章不会触发拦截。

**判结果**：`document-start` 阶段 hook `fetch` / `XHR`，点击后只采信签到相关路径的响应；普通 `POST` 的 `success:true`、`code:0` 等通用字段不会单独算成功。读不到响应就退回读点击后新出现的 toast 提示，再看页面是否出现新的已签状态。按钮置灰本身不算成功，仍没有明确证据时标记为「待确认」。

不显示余额。余额只能靠字段名（`balance`/`quota`/`amount`…）和 class 关键词去猜，很容易把签到奖励、连续天数之类的数字当成余额，显示错的比不显示更糟。要看余额直接翻标签页。

## 遇到情况会怎样

| 情况 | 行为 |
|---|---|
| 人机验证 | 停下，提示你手动完成。不尝试绕过 |
| 未登录 | 停下，提示你手动登录（仅访问模式同样检查） |
| 页面失效（404 等） | 标记失效，不重试 |
| 找不到按钮 | 列出页面上的可点击文案，供你补充匹配规则 |

需要你处理的站点，标签页会保留不关，页面上有一条红色提示说明卡在哪一步（点一下才消失）。面板里那条结果下方有「切到那个标签页 →」，点它会切到原来那个标签页，不是新开。

油猴没有「聚焦已存在标签页」的接口，所以实现上是面板往共享存储写一条请求，目标标签页自己收到后调 `window.focus()`。如果那个标签页已经被你关掉了，700ms 内没人响应，才会退回新开一个。浏览器有时会拦下后台页面的 `focus()`，这种情况标签页标题会闪烁提示，你手动切过去即可。

找不到按钮时，点面板里那一行的 `⋯` → 「补充按钮文案」，把实际文案填进去。只对该站点生效。

## 设置

- 站点间隔：默认随机 3-8 秒
- 签完自动关闭标签页：默认关（留着让你核对）
- 补充签到按钮文案：站点按钮文案不在默认表里时填这里
- 等按钮超时 20 秒、等结果 20 秒、单站点整体超时 90 秒
- 关掉挡路的公告弹窗：只关确定是关闭控件的，弹窗内有签到按钮时不关

## 开发

```bash
node build.js              # src/ 拼成单文件
node --test test/*.test.js # 运行全部测试
```

`src/` 按文件名顺序拼接：

| 文件 | 职责 |
|---|---|
| `10-storage.js` | `GM_*` 封装、跨标签页状态 |
| `20-site.js` | 站点模型、名称自动获取与锁定、编辑校验 |
| `30-detect.js` | **按钮识别**（核心） |
| `31-guards.js` | 人机验证、登录页、失效页判断 |
| `40-checkin.js` | 签到流程、网络 hook、点击 |
| `41-verdict.js` | 从响应和页面读结论 |
| `50-worker.js` | 站点页上执行并上报 |
| `52-focus.js` | 标签页自我聚焦（面板点「切过去」时用） |
| `60-coordinator.js` | 批量调度 |
| `7x-ui-*.js` | 浮层面板 |
| `90-main.js` | 角色判断入口 |

测试用 `test/dom-stub.js` 提供最小 DOM，不引外部依赖。`test/load-src.js` 用 `new Function` 在主 realm 求值源码，所以测的和构建产物是同一份代码。

`test/structure.test.js` 用正则锁定架构约定，其中这几条是刻意的，不要放宽：

- 不出现签到接口路径，不主动发签到请求
- 人机验证只中止、不绕过
- 网络 hook 在 `document-start` 安装
- `GM_openInTab` 原样传入 `visitUrl`，不往 URL 加任何标记（hash 路由会被改坏）
- 任务认领靠时间窗口 + `claimedAt` 标记，只认领一次
- 不做余额提取（靠猜的数字不如不显示）
- 点击后的缓冲期内不采信「按钮置灰」（转盘动画期间按钮就是灰的）
- 签到结果弹窗不被 `closeBlockingDialogs` 关掉
- 标签页默认保留，只在显式开启 `autoCloseTab` 时才自动关
- 「切到标签页」先发聚焦请求，只在无人响应时才 `GM_openInTab` 兜底
- `watchFocusRequests` 在认领任务之前装，没被派活的页面也要能被切过来
- 手动改过的站点名不被自动获取覆盖（`nameLocked`）
- 自动取名先整体判断功能词再按分隔符拆分，否则 `Check-in` 会被拆成 `Check` 漏过过滤
- 面板输出经 HTML 转义

## 与扩展版的差别

扩展版（仓库根目录）保留不动。差别：

| | 扩展版 | 油猴版 |
|---|---|---|
| 主路径 | 按类型调签到接口 | 点页面按钮 |
| 站点配置 | 域名 + 类型 + 模式 | 签到页地址 |
| 定时 | `chrome.alarms` 每日自动 | 无，手动触发 |
| 认证 | 抓请求头、读 cookie、OAuth 编排 | 不管，用页面自己的会话 |
| 代码量 | ~6900 行 | ~2100 行 |

## 风险

这类站点的服务条款通常禁止自动化签到，封号风险你自己承担。

签到请求由页面自己发出，比手工重建请求头更接近手动操作。但连续处理多个站点仍是可观测的行为，随机间隔只降低规律性、不能消除。什么时候用比脚本怎么写更影响风险。
